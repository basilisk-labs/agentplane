# Docs update recipe

A docs-update Recipe can contribute guidance for source-backed documentation edits and required link/schema checks. It does not execute arbitrary YAML
`steps`, run commands on installation, or own a separate workflow lifecycle.

Use the [Scenario V2 authoring contract](../developer/recipes-development) and its validated
[read-only example](../examples/recipes-v2/scenario.json) as a structural starting point. Adapt the
objective, mandatory criteria, checks and exact writable scope to the actual repository. A TDD,
docs or security scenario must not borrow approval from that example or assume tools exist.

Review the actual package/version before local installation and vendoring:

```bash
agentplane recipes install --path ./reviewed-recipe.tar.gz
agentplane recipes add <recipe-id>@<version>
agentplane recipes explain <recipe-id>
agentplane recipes preview-v2 selection.json
```

For approved task intake, supply explicit selection through `task create --recipe-file` or
`task plan set --recipe-file`. Follow native preparation/retention instructions and the ordinary
USER approval boundary. Continue via `task advance --agent-json` or a configured `task run`.
The required independent EVALUATOR, verification and task evidence owners remain unchanged.

Legacy V1 steps are source context, not an imperative DSL. Audit them with `recipes preview-v1`
and preserve unsupported obligations during bounded conversion. Stop when evidence or authority
is insufficient. No recipe removes the normal no-Recipe route or establishes measured savings.
