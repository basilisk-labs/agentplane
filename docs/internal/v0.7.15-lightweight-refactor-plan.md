# AgentPlane 0.7.15 lightweight refactor plan

Status: proposed program. Owner approval for the first wave was given in the authoring session.
Baseline: `9d04dcff6` (AgentPlane `0.7.14-beta.1`), audited 2026-11-23.

## Outcome

Make AgentPlane lighter, faster, and easier to adopt without weakening its trust model:

- fewer files, bytes, and commits per task in the user's repository;
- faster read commands on repositories with long task history;
- a smaller CLI surface and a shorter always-loaded agent instruction set;
- less duplicated control-plane code, measured by deleted LOC rather than file splits.

Non-goals: changing the authority model, removing evidence that a reviewer needs, or replacing the
Task Kernel. Every task below must keep `ci:contract` and `ci:test` green.

## Rules for every task

1. One task is one reviewable commit (or a short series) that leaves the repository green.
2. Measure before and after. Record the numbers in the commit message.
3. Preserve on-disk compatibility. A format change ships with a reader for the old format and a
   migration command; deletion of the old reader is a separate, later task.
4. Prefer deleting code over moving it. A split that only satisfies the line cap is not progress.

## Ordering

Wave 1 has no dependencies. LW-11 → LW-12 → LW-13 → LW-15 share the evidence reader and should run
in order. LW-14 depends on LW-13. LW-19 and LW-20 are independent. LW-23 and LW-24 need LW-06 and
LW-26 first, so regressions are visible.

## Process note

This program was started in a cloud checkout where the repository's own task records could not be
advanced (see LW-02 and LW-04). The owner approved committing the Wave 1 repairs without task
bindings; such commits carry an `AgentPlane-Override` trailer and list the checks that were run
manually. Once LW-04 is fixed, later waves should run through the normal `task advance` protocol.
