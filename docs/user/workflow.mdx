## Default path

Agentplane owns process state, repository routing, approvals, verification persistence, hosted gates,
integration, and closeout. Agents receive only bounded semantic work that benefits from reasoning.

The normal agent-facing surface is:

```bash
agentplane task active
agentplane task advance <task-id> --agent-json
```

When the packet returns `action.kind=agent_episode`:

1. Perform only its semantic objective.
2. Stay inside its authority and writable roots.
3. Write the typed result to `exchange.directory/exchange.result_ref`.
4. Resume through `exchange.return_invocation` and request a fresh packet.

For a configured managed adapter, use:

```bash
agentplane task run <task-id>
```

The managed and external frontends consume the same route, fingerprint, WorkOrder, evidence model,
and stop boundaries. A newly created task still needs its initial PLANNER result through
`task advance`; after planning and approval, either frontend may resolve an eligible semantic
episode.

## Agent-selected execution strategy

The PLANNER interprets the task and returns a structured execution declaration. It chooses a
preferred `direct` or `branch_pr` strategy and declares repository scope, expected repository and
external effects, uncertainty, reversibility, and rationale. Agentplane does not infer these facts
from product-language keywords such as `production`, `release`, `docs`, `server`, or `deployment`.

Agentplane compiles the declaration into one deterministic execution contract:

- `authority` lists writable roots plus allowed and forbidden effects;
- `safety` lists required approvals and whether a worktree is required;
- `verification.required_evidence` is derived from declared effects;
- `observed` accumulates changed paths, components, external capabilities, and check results.

A declaration describes intent but cannot self-authorize deploy, publish, credentials, external
writes, or destructive Git. A declared read-only network effect can be delegated, while `safety`
still requires the configured approval boundary before an execution WorkOrder is issued. High-risk
external effects remain forbidden after plan approval and require their own control-plane action.

If objective observations exceed a compatible `direct` declaration, Agentplane preserves the
implementation commit and changed paths, strengthens evidence, and emits one `branch_pr` handoff.
It does not require the agent to run reclaim, reconcile, or repair commands. Once branch-specific
state exists, the route never downgrades to `direct`.

The realistic CLI contract suite records the following control-plane measurements. Verification
time is `0 ms` for routing-only scenarios; executable checks are timed and retained separately in
the task verification record rather than being rerun for every routing assertion.

| Scenario                                               | Control-plane commands |                              Approval boundaries | Work preserved          | Recovery commands |
| ------------------------------------------------------ | ---------------------: | -----------------------------------------------: | ----------------------- | ----------------: |
| Local reversible or misleading-language direct route   |                      4 |                                      1 plan gate | not applicable          |                 0 |
| Broad SDK/schema `branch_pr` route                     |                      4 |                                      1 plan gate | not applicable          |                 0 |
| Underestimated `direct` route                          |                      6 |                                      1 plan gate | commit and changed path |                 0 |
| Prohibited deploy/destructive effects                  |                      4 | 1 plan gate, external authority remains required | not executed            |                 0 |
| Approved read-only network access                      |                      5 |                             1 user approval gate | not executed            |                 0 |
| Existing contract through completed `direct` lifecycle |                      7 |                                      1 plan gate | changed path recorded   |                 0 |

Compared with manually choosing task kind, process profile, mutation class, risk flags, and route,
the normal path has no manual mode-selection command and no recovery-command sequence. Significant
work still receives `branch_pr`, hosted-integration evidence, and explicit external authority.

## First managed workflow

```bash
agentplane task create "Fix the reported defect"
agentplane task advance <task-id> --agent-json
agentplane task advance <task-id> --result <exchange-directory>/result.json --agent-json
```

Give the first packet to an external PLANNER, write its typed result to the packet's exchange
directory, and return it with the second command. Agentplane persists the plan and emits the exact
operator action if human approval is required. After approval, continue with:

```bash
agentplane task run <task-id>
```

Before the PLANNER result exists, `task run` returns `semantic_input_required` and does not invoke
the managed adapter. After planning and approval, rerun it only after resolving the exact human,
external, or recovery boundary Agentplane returned.

## direct mode

In `direct`, Agentplane keeps work in the current checkout. It owns formal start, verification
records, evaluation, and closeout. The agent still receives only the semantic objective and allowed
write scope.

## branch_pr mode

In `branch_pr`, Agentplane creates or selects the task worktree, prepares context from that checkout,
publishes the task branch and PR, waits for hosted checks, integrates, and closes the task. The caller
does not change directory or reconstruct branch state manually.

## Trust boundaries

- `state_fingerprint` prevents stale semantic results from mutating newer task state.
- `authority` limits mutation, network, and external actions for the current episode.
- `ExecutionReceipt` proves that Agentplane observed the runner outcome.
- Independent evaluation can return pass, rework, blocked, or human review.
- Approval, human, external, and terminal boundaries return control instead of being simulated.

## Diagnostics and compatibility

The following are operator/recovery surfaces, not the normal agent loop:

```bash
agentplane task brief <task-id>
agentplane task status <task-id> --route
agentplane task next-action <task-id> --explain
agentplane doctor
```

Low-level lifecycle, branch/worktree, Git publication, PR, verification persistence, integration,
cleanup, and release commands remain available for explicit recovery and compatibility. Agents must
not invoke them during a normal semantic episode.

For the end-to-end evidence model, see [Task lifecycle](task-lifecycle).
