# Add documents to context

Use context learning when source material should become reusable project knowledge.

## Learn from files

```bash
agentplane context learn files ./notes.md
agentplane context learn files ./docs/specs
```

This creates a `CURATOR` task. The agent should read the source set, search existing context, and
write sourced updates.

## Learn from changed context sources

```bash
agentplane context learn changes
```

Use this after editing `context/**` by hand.

## Learn from completed tasks

```bash
agentplane context learn tasks --tag release --limit 20 --dry-run
agentplane context learn tasks --tag branch_pr --limit 25
agentplane context learn tasks --task 202605100837-PJZW2E
```

This first turns only explicitly marked durable task history into source-backed, unpublished knowledge proposals. Before a
single explicit `--task` selection creates one CURATOR semantic work order, the CLI freezes a
canonical pre-selection check: source hashes, addressable lexical candidates, and a recorded
`clear` or `consolidation_required` result. A candidate never becomes a CLI decision about semantic
equality; CURATOR receives the evidence and performs reconciliation. The selection lease has an
owner and expiry, so an interrupted handoff can be safely recovered without creating a second owner.

## Agent write order

1. CLI records the selected source set, hashes, candidate signals, and pre-selection canonical duplicate/consolidation evidence.
2. CURATOR searches canonical wiki, facts, graph, and glossary, then returns one semantic SGR.
3. CLI validates and materializes an accepted result, reindexes, runs checks, evaluates it, and records the apply receipt.

## Avoid duplicates

If a source has addressable lexical candidates in current knowledge, the pre-selection check records
`consolidation_required`; CURATOR records the duplicate or consolidation reasoning in the semantic
result. The CLI never selects a canonical page or merges knowledge by itself.
