---
title: "branch_pr workflow"
description: "Use Agentplane branch_pr mode while the supervisor owns worktrees, PR evidence, hosted checks, and integration."
---

Use `branch_pr` when implementation should remain separate from the base checkout until review and
hosted checks complete.

The responsibility split is:

- The human chooses the task, approval, review, and publication boundaries.
- The semantic agent implements or reviews one bounded objective.
- Agentplane owns branch/worktree routing, task state, PR artifacts, verification persistence,
  hosted waits, integration, close evidence, and cleanup.

## When to use

- Multiple people or agents may work near the same repository.
- Integration should happen only after review or hosted checks.
- You want PR metadata and verification artifacts per task.

## External agent

Give the agent a task id and use the compact protocol:

```bash
agentplane task active
agentplane task advance <task-id> --agent-json
```

When the packet returns `action.kind=agent_episode`, the agent performs only that objective in the
authoritative worktree and writable roots supplied by Agentplane. It writes the typed result to
`exchange.result_path` and resumes with the exact `exchange.resume_argv`;
`exchange.return_invocation` is compatibility-only.

The caller does not create branch names, change cwd, publish the PR, persist verification, merge,
or clean the worktree.

## Managed runner

With a configured adapter, use:

```bash
agentplane task run <task-id>
```

The managed and external routes share the same state fingerprint, WorkOrder, authority, semantic
result, verification boundary, and execution journal. Both stop for human approvals and hosted or
external work.

## Expected repository evidence

- a task branch and worktree managed by Agentplane;
- `.agentplane/tasks/<task-id>/pr/` review artifacts;
- observed verification and evaluator evidence;
- hosted PR/check and integration identity;
- pre-merge or hosted close evidence;
- safe merged branch/worktree cleanup.

These are CLI-owned process artifacts. The semantic agent may read referenced evidence but must not
edit or recreate it unless the current WorkOrder explicitly makes that artifact the semantic
objective.

## Diagnostics and recovery

For human/operator investigation:

```bash
agentplane task brief <task-id>
agentplane task status <task-id> --route
agentplane task next-action <task-id> --explain
agentplane doctor
```

Low-level branch, PR, verification, integration, close, and cleanup commands are available through
`agentplane help --all`. Use them only when Agentplane returns an explicit operator/recovery route;
they are not the normal coding-agent prompt.

## Limitations

`branch_pr` adds hosted and worktree overhead. Per-task automatic routing can keep small, safe work
in `direct` and escalate tasks that need isolation. Configure a repository-wide `branch_pr` floor
when every task must use that boundary.
