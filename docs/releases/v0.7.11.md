# Release Notes — v0.7.11

AgentPlane 0.7.11 completes lifecycle convergence around the Task Kernel. One application
coordinator now owns ordinary, managed, Recipe V1, direct, and branch-PR progress while preserving
the existing authority, context, verification, review, recovery, hosted-integration, and
effect-in-doubt boundaries.

## Summary

- Make the Task Kernel the sole live domain reducer and mutation gateway, with one shared
  advance-one-step coordinator for every supported execution route.
- Unify scheduling, semantic WorkOrder dispatch, result admission, context preparation, native
  verification, independent review, recovery, and terminal completion around the same canonical
  state and evidence boundaries.
- Remove superseded lifecycle engines, duplicate outer supervisors, reverse synchronization,
  obsolete exports, and no-information terminal writes after replacement behavior is proven.
- Qualify the converged implementation through installed-package, migration-race, safety,
  architecture, compatibility, replay, and post-convergence test-topology gates.

## Added

- Add an explicit lifecycle-owner map that identifies the canonical writer, scheduler, admission
  boundary, completion owner, and effect owner for every production entrypoint.
- Add guarded preview and apply flows for lifecycle-owner migration into the Task Kernel, including
  source-digest, authority, revision, quiescence, and rollback-proof fences.
- Add executable post-convergence behavior-to-test and test-to-CI-route ledgers for retained
  authority, concurrency, recovery, migration, and effect-in-doubt invariants.
- Add deterministic 0.7.10 versus 0.7.11 replay evidence with equal mandatory role obligations and
  all assigned attempts retained. No paid-provider efficiency claim is made.

## Improved

- Route Plan and WorkItem mutations through one backend transaction and Kernel command/event
  contract; compatibility status and README fields are projections rather than competing writers.
- Reuse one dependency, output, optional-item, and resource-claim readiness calculation instead of
  maintaining parallel schedulers.
- Use one WorkOrder and semantic result-admission boundary across managed and external transports,
  including exact lease, fingerprint, identity, authority, freshness, and structure checks.
- Preserve CURATOR and bounded context preparation in the common path without allowing an executor
  to treat requested knowledge as already present.
- Run native verification before independent review where required, reuse only matching immutable
  evidence, and keep EVALUATOR independence and rework semantics intact.
- Route direct finalization, branch worktree preparation, hosted checks, integration, close-tail
  transitions, and Recipe V1 execution through shared coordinator operations.
- Reconcile completed, pending, failed, and uncertain effects before new scheduling so restart and
  recovery cannot duplicate external work.
- Make managed `task run` a transport loop around canonical one-step advancement instead of a
  second lifecycle engine.
- Document the sole lifecycle contract and the formal-versus-semantic decision boundary without
  introducing optional mandatory stages in this release.
- Consolidate equivalent test fixture setup and assign retained cases to the smallest correct suite
  while preserving their behavior-level oracle.

## Fixed

- Persist branch-PR terminal Task Kernel completion before the terminal task-artifact commit, so a
  clean committed task README records `DONE` and `COMPLETED` rather than lagging canonical state.
- Resolve registered branch worktrees by parsed task identity and fail closed on ambiguity, while
  preserving fresh-worktree bootstrap and deterministic validation-rework behavior.
- Project canonical plan approval into compatibility fields used by branch routing instead of
  leaving an approved Kernel plan invisible to the route.
- Prevent terminal replay from rewriting checkpoints, generated views, timestamps, or commits when
  authoritative state is already complete and no effect remains unresolved.
- Reject conflicting outer and Kernel state, stale or cross-task semantic results, forged approval,
  missing required outputs, and unsafe migration races instead of choosing a permissive path.
- Keep the public compatibility candidate synchronized with the exact current source provenance
  while leaving the immutable published 0.6.24 baseline unchanged.

## Upgrade Notes

- The CLI, `@agentplaneorg/core`, `@agentplaneorg/recipes`, and `@agentplane/testkit` move together
  to 0.7.11 with exact internal dependency versions.
- Existing ordinary, managed, direct, branch-PR, and Recipe V1 commands remain the supported public
  entrypoints; engine-selection and superseded lifecycle APIs are no longer active execution paths.
- Historical records remain readable through the retained cold compatibility and migration
  boundaries. Do not hand-edit task state or recreate removed supervisors.
- Preview managed-file changes with `agentplane upgrade --dry-run`, then apply the reviewed upgrade
  with the repository's normal `agentplane upgrade` flow.

## Verification

- The candidate is required to pass release parity, registry availability, release notes, package
  reference generation, packed-install smoke, release-critical tests, architecture, compatibility,
  clone, unused-export, schema, documentation, replay, and full local CI gates.
- Hosted publication remains bound to the exact protected-main SHA and its successful
  `release-ready` artifact before npm packages, tag, GitHub Release, standalone distributions, and
  package-manager evidence are created.
- The measured replay disposition is evidence-only: lifecycle convergence is qualified, but a paid
  token, cost, or latency improvement is not established by this release.
