# Release Notes — v0.7.9

AgentPlane 0.7.9 strengthens the path from an approved task to verifiable completion. The release makes task execution, recovery, evaluation, provider integration, and release evidence agree on the same repository state. It also records provider-observed token usage without assuming that a subscription-backed agent run is a direct monetary purchase.

The release keeps authority boundaries explicit while reducing manual recovery work. Branch and pull-request state is reconciled through state-bound operations, CLI behavior is covered across Node, Bun, Windows, installed-package, and hosted workflows, and the documentation now describes the same task lifecycle that the runtime enforces.

## Summary

- Keep semantic agent work separate from lifecycle, provider, and release operations while preserving one auditable task record.
- Recover stale, interrupted, or externally completed work without accepting results for the wrong task, revision, commit, or provider state.
- Project provider-observed token usage for agent attempts while leaving token-limit enforcement disabled unless it is explicitly configured.
- Qualify the 0.7.9 candidate across local, installed, hosted, Windows, security, documentation, and release-critical surfaces.

## Added

- Add provider-observed token accounting and task-level usage reporting with explicit unavailable and unallocatable states.
- Add paired production measurement artifacts that preserve every assigned attempt and keep unsupported efficiency conclusions marked as not established.
- Add state-bound recovery and evidence paths for task worktrees, external results, evaluator review, hosted integration, and release publication.

## Improved

- Improve branch and pull-request lifecycle convergence across local Git, GitHub, GitLab, hosted close, integration queues, and cleanup.
- Improve installed runtime, Bun, Node, Windows, package, documentation, and security qualification without changing the supported public command contract.
- Improve task prompts and documentation with simpler technical language, clearer authority ownership, and exact stop conditions.

## Fixed

- Reject stale or mismatched semantic results, evaluator evidence, provider mutations, and release inputs instead of inferring success from partial state.
- Preserve unrelated dirty work and source-only roadmap material during task routing, verification, integration, and cleanup.
- Keep generated release surfaces, package manifests, CLI entrypoints, distribution metadata, and hosted evidence synchronized with the exact candidate.

## Upgrade Notes

- The CLI, `@agentplaneorg/core`, and `@agentplaneorg/recipes` move together to 0.7.9 with exact matching internal package versions.
- Existing projects should preview managed-file changes with `agentplane upgrade --dry-run`, then apply them with `agentplane upgrade --auto --yes --migrate-task-docs` when the preview is acceptable.
- Existing task data remains outside managed-file replacement, and normal agent work continues through `agentplane task advance <task-id> --agent-json` or a configured managed runner.

## Verification

- Candidate admission requires `bun run release:check`, `bun run release:prepublish`, independent evaluation, hosted Core CI, and protected integration for the exact candidate commit.
- Publication requires the protected release workflow, an exact-SHA `publish-result.json` with no failures, and independent readback of GitHub, npm, setup-agentplane, Homebrew, Scoop, and both CLI entrypoints.
- The frozen release base is `ecfccc5ad0230fc1876a319be0af5cdb530c339f`, after PR #5949 and its hosted close completed.
