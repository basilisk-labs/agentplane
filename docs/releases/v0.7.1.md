# Release Notes - v0.7.1

## Summary

- AgentPlane 0.7.1 makes the shared task supervisor the default operating model: the CLI prepares formal context, lifecycle state, authority, and evidence while agents retain semantic planning, implementation, synthesis, and review.
- The frozen provider qualification completed 50 runs across 55 provider episodes with zero blockers and reduced measured token use by 29.921280763879005%, from 9,070,337 to 6,356,376 tokens.
- The same gate improved verified success from 5 to 20 cases, reduced rework from 36 to 25, reduced scope violations from 20 to 5, and reduced golden mismatches from 46 to 10.
- The canonical help surface is now bounded to 11 primary operations, with compatibility commands hidden from the normal path.

## Added

- Added one compact external-agent action packet through `task advance --agent-json`, capped at 2,048 bytes and backed by the same supervisor engine as `task run`.
- Added completed-task token accounting with input, output, reasoning, total, provenance, completeness, and an explicit unavailable state when no supervisor journal exists.
- Added a compatibility retirement manifest and `doctor legacy --json` inventory so legacy adapters have visible ownership and expiry instead of indefinite implicit support.
- Added exact-candidate RF-04 pilot support and a reproducible 50-run / 55-episode qualification contract for release decisions.

## Improved

- Unified direct, branch PR, evaluator, and context execution around typed next actions, observed receipts, explicit authority, restart-safe journals, and content-addressed evidence.
- Reduced agent cognitive load by removing redundant Git observations, bounding context packets, deduplicating immutable evidence, and keeping mutable task, provider, and policy truth live.
- Adopted native TypeScript 7.0.2 for repository typechecking and reduced the Knip baseline to 21 core-only findings, with zero unused-file, export, or type findings in the CLI package.
- Kept user-facing release outcomes concise while placing the complete commit-level qualification ledger in a collapsed audit section below.

## Fixed

- Fixed stale-runner recovery coverage so a missing recorded PID cannot surface as `E_INTERNAL`: claimed runs cancel and route to retry, while unclaimed runs fail closed with typed `E_RUNTIME`.
- Fixed synthetic-plan leakage: semantic planning must be supplied by the planning agent, and compatibility `task begin` no longer invents an executable plan.
- Hardened compatibility completion so normal `task complete` requires observed verification or review; unobserved acceptance remains explicitly unsafe and confirmation-gated.
- Removed obsolete local and remote task branches, stale worktrees, and the superseded `agentplane-loops` product line while preserving active, blocked, dirty, maintenance, and recovery evidence.

## Upgrade Notes

- Upgrade with `npm install --global agentplane@0.7.1`, then run `agentplane upgrade --dry-run`, the approved upgrade command, and `agentplane doctor`.
- Projects already on 0.7.0 do not need a new workflow migration; the release is compatible with the 0.7 contracts and adds supervisor, recovery, efficiency, and release-readiness hardening.
- Compatibility commands remain callable for migration, but the supported daily path is `task new` → `task advance --agent-json` → `task run`.
- The experimental `ap loop` line is intentionally not part of 0.7.1; bounded iteration, budgets, recovery, and evaluator control are provided by the shared task supervisor.

## Verification

- The final product qualification passed 18 of 19 scenarios, 50 replay runs, 55 provider episodes, all supervisor and matched-CLI latency gates, and the independent quality evaluator with zero release blockers.
- Deterministic qualification covered the v0.7.1 product contract, TypeScript 7, static analysis, critical CLI paths, workflow recovery, package tarballs, installed migration scenarios, and protected-main publication controls.
- The only remaining absolute CLI latency signal is advisory; matched CLI and supervisor latency thresholds passed and no unsupported latency claim is made.
- Publication remains exact-SHA: the release candidate must merge to protected main before the npm workflow is dispatched, followed by tag, GitHub Release, registry parity, installed smoke, and postpublish verification.
