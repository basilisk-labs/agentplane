# Release Notes — v0.6.29

## Summary

- Hook shims now choose only runners that can start successfully, while preserving explicit operator overrides and genuine hook failures.
- Developer global installs now use materialized package tarballs instead of links into a mutable source checkout.
- Evaluator reviews and task-run status expose more reliable commit identity and runtime activity evidence.
- The repository toolchain is qualified and pinned to Bun 1.4.2 without changing the Node, Vitest, tsup, or dependency-resolution contracts.

## Added

- Added bounded `--version` readiness probes for explicit, repository-local, installed, and opted-in global hook runners.
- Added task-run activity fields for the latest trace timestamp and sequence, elapsed time since activity, and `active`, `idle`, `exited`, or `unknown` health.
- Added regression coverage for direct-task rework routing so the existing v0.6 recovery path remains mutable after verification requests changes.

## Improved

- Explicit `AGENTPLANE_HOOK_RUNNER` configuration takes precedence, while an unavailable candidate falls through before hook execution and a real hook rejection still fails closed.
- `agentplane doctor` identifies stale managed hook shims that lack startup-readiness checks and points operators to `agentplane hooks install`.
- The developer reinstall workflow packs and installs `agentplane` and `@agentplaneorg/core` artifacts, then verifies their build manifests against the current source revision.
- Release workflows now use Bun 1.4.2 consistently across local and hosted commands while keeping `bun.lock` unchanged.

## Fixed

- Fixed evaluator review identity selection so an unrelated task-artifact commit cannot produce a successful review with a missing or drifted evaluated SHA.
- Fixed task-run status so recent trace or stderr activity prevents a healthy runner from appearing stalled when its process heartbeat is unchanged.
- Fixed managed pre-commit hooks selecting an incomplete local runner without trying an explicitly configured or otherwise ready fallback.
- Fixed global development installs remaining coupled to a source checkout that another concurrent task can move or remove.
- Removed unnecessary public exposure of the internal runner-health union and kept generated hook code compatible with the CLI legacy-pattern guard.
- Fixed first pushes in newly initialized projects without a broad local CI script, and moved the ESLint flat config to native ESM so current Node 24 runtimes load ESM-only plugins reliably.

## Upgrade Notes

- No configuration migration is required.
- The published package set moves from `0.6.28` to `0.6.29`.
- Re-run `agentplane hooks install` in repositories whose Doctor output reports an older managed hook shim.
- Developers who use `scripts/workflow/reinstall-global-agentplane.sh` will receive detached package installations instead of global source links.
- The broader task-pinned executable architecture remains a v0.7 concern; this patch hardens the applicable v0.6 install and hook boundaries only.

## Verification

- Focused evaluator, runner-health, direct-rework, hook-shim, Doctor, global-install, and release-contract regressions pass.
- Full fast CI passes 371 test files and 2,190 tests, followed by 14 critical CLI tests.
- Platform-critical tests, type checking, linting, formatting, workflow command contracts, Bun compiled-CLI smoke, tarball installation smoke, release checks, policy routing, and the knip baseline pass.
- Hosted Linux, Windows, static, unit, coverage, contract, workflow, documentation, review, and actionlint checks passed on the merged maintenance implementation.
