# Release Notes — v0.6.28

## Summary

- Direct task routing no longer recommends `agentplane task run` when no managed runner is active.
- The v0.6 task flow keeps `task next-action` as its route oracle and assigns semantic execution to the current coding agent.
- Explicit managed-runner commands remain available as compatibility and operator surfaces.

## Added

- Added regression coverage proving that a tracked direct task without runner state stays on the current-agent route.
- Added regression assertions that route recomputation does not reintroduce a `task run` recommendation.

## Improved

- Direct execution guidance now returns `continue_direct` and points to `task verify-show` as the contract to consult before recording verification.
- CLI help now describes the guided path as `task next-action`, current-agent execution, and verification, while preserving the diagnostic role of `task next-action`.
- Task supervision evidence records the approved correction from the initial over-broad route interpretation to the final v0.6-compatible behavior.

## Fixed

- Fixed the default direct route incorrectly sending agents to the managed task runner instead of having the current agent perform the task.
- Fixed resume and recomputation fallbacks that could restore `task run` guidance when no runner owned the task.

## Upgrade Notes

- No migration or configuration change is required.
- The published package set moves from `0.6.27` to `0.6.28`.
- This maintenance patch is based on `v0.6.27` and does not backport the v0.7 `task advance` protocol.

## Verification

- Focused route-decision, task-guidance, route-guidance, and command-catalog tests cover the corrected route contract.
- Routing policy validation, version parity, the complete prepublish suite, hosted PR checks, exact-SHA publication, and npm registry readback are required before final closure.
