# Release Notes — v0.6.27

## Summary

- `task reclaim` now recovers a runner whose persisted PID is valid but no longer exists.
- Process identity inspection now recognizes the actual non-zero `ps` result shape returned by the process runner.
- Reclaim regression coverage now uses a real exited process instead of an out-of-range synthetic PID.

## Fixed

- Fixed `task reclaim` failing after `task run status` reported `pid_alive: false`.
- Fixed `readObservedProcessIdentity` reading only `error.code` even though the underlying `ExecaError` exposes a missing-process result as `error.exitCode = 1`.
- Preserved the fail-closed identity check for live PIDs, so reclaim cannot signal an unrelated process after PID reuse.

## Upgrade Notes

- No migration or configuration change is required.
- The published package set moves from `0.6.26` to `0.6.27`.
- This maintenance patch is based on `v0.6.26` and is intentionally isolated from current `main` development.

## Verification

- The CLI regression creates a real child process, waits for it to exit, stores that valid dead PID in runner state, and proves reclaim persists `cancelled` state.
- Focused reclaim and runner lifecycle tests, formatting, release parity, the complete prepublish suite, hosted checks, exact-SHA publication, and npm registry readback are required before final closure.
