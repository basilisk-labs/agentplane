# Release Notes — v0.6.26

## Summary

- Direct-workflow tasks that are `DOING`, still need verification, and have no runner state now receive an executable `task run` transition instead of a successful but state-neutral `verify-show` loop.
- Terminal runner states now stop with explicit verification guidance and no executable command, preventing the route oracle from repeatedly returning a read-only command.
- Canonical task artifacts are persisted before direct execution, and pre-merge closure evidence is invalidated when later implementation commits make its basis stale.

## Added

- Added an exact regression for `DOING + verification pending + no runner state`, including recomputation after a dry-run runner preparation. (d60e737)
- Added coverage for untracked canonical task artifacts that proves the guarded persistence commit leaves unrelated untracked files untouched. (d60e737)
- Added a terminal-runner regression proving successful runner state produces a non-mutating verification stop with no `exactArgv`. (d60e737)
- Added a stale pre-merge closure regression that exercises the deterministic `pr update` followed by fresh closure route. (ccfacd7)

## Improved

- `task begin` now hands direct workflows back to `task next-action --explain`, keeping the route oracle authoritative instead of hard-coding a read-only verification command. (d60e737)
- Runner hints no longer advertise `verify-show` after terminal success; they expose an explicit no-command stop so automation cannot mistake inspection for progress. (d60e737)
- Direct DONE cleanup now includes untracked canonical task artifacts in the guarded task-only commit. (d60e737)
- The oversized route-test budget remains within the frozen baseline after the new regression coverage was compacted. (1997cf2)
- Hosted contract evidence for the direct routing changes was recorded after the first CI correction. (9836609)
- Pre-merge closure freshness now compares its `basis_commit` with the current implementation head while allowing only task-artifact-only advances. (ccfacd7)
- Static validation now reads untracked paths before filtering them, preserving routing behavior while satisfying the repository lint contract. (ff8da41)

## Fixed

- Fixed the infinite `verify-show` loop for direct tasks that need work but have no runner state.
- Fixed the contradiction where a route could describe a successful terminal runner and still emit a state-neutral command as executable.
- Fixed the persistence gap that allowed `.agentplane/tasks/<task-id>/` artifacts to remain untracked before runner execution.
- Fixed stale pre-merge closure markers being accepted after new implementation commits.
- Fixed PR artifact precedence for reworked tasks so stale PR metadata is refreshed before a new closure marker is recorded.

## Upgrade Notes

- No breaking changes are introduced by this patch release.
- The published package set moves from `0.6.25` to `0.6.26`.
- No migration or configuration change is required.
- Publication is intentionally based on `codex/fix-v0.6.24-closeout-route`; this maintenance release is not merged into `main`.
