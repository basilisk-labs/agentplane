# Release Notes - v0.7.0

## Summary

- Agentplane 0.7 makes the CLI the mechanical authority for context preparation, state observation, lifecycle transitions, side-effect authorization, evidence capture, and reproducibility while agents retain semantic planning, implementation, synthesis, and review.
- Every supervised agent episode now uses a bounded, versioned work order with typed results, state fingerprints, durable operation identity, explicit stop rules, and independently observed execution receipts.
- Direct, branch PR, evaluator, and context workflows now share resumable supervision, fail-closed effect recovery, deterministic route guidance, bounded knowledge retrieval, and protected provider handoffs.
- The release includes a complete migration path from fresh, 0.6.24, and 0.6.26 repositories, native TypeScript 7 typechecking for maintainers, current public documentation, and exact-SHA publication controls.

## Added

- Added AgentWorkOrder v2, AgentSemanticResult v2, ExecutionReceipt v2, KnowledgeRef v1, StateFingerprint v1, and typed WorkflowStep v1 contracts with generated schemas and compatibility fixtures.
- Added explicit authority records that bind protected side effects to an operation digest and current state scope instead of accepting a model claim as permission.
- Added durable effect journals and typed effect-in-doubt resolution so retries, restarts, timeouts, and cancellation cannot silently duplicate an unresolved provider action.
- Added a shared bounded supervisor for direct, branch PR, evaluator, and context episodes with persisted cursors, budgets, progress fingerprints, and restart-safe checkpoints.
- Added read-only evaluator execution with frozen work orders, observed checks, structured pass or rework results, bounded recovery context, and evidence-selected review targets.
- Added SQLite FTS5 and BM25 context retrieval, incremental projection updates, source-driven canonical candidates, deterministic task knowledge retrieval, and policy-gated semantic escalation.
- Added phase-scoped runtime tools and granular CommandSession capabilities so each command receives only the filesystem, Git, provider, lifecycle, or artifact authority required for its current phase.
- Added preparation-graph instrumentation, deterministic invalidation inputs, RF-04 replay telemetry, installed migration scenarios, and release-closure manifests for measurable orchestration quality.

## Improved

- Made task brief and task next-action the authoritative agent-facing route surfaces, including the exact checkout, blocker, role, safe command, authority requirement, and return condition.
- Unified runner, Hermes, task lifecycle, context, evaluator, provider, integration, and release commands behind typed use-case and rendering boundaries.
- Preserved the repository-owned context wiki as the durable knowledge plane while work orders carry only digest-addressed references, bounded excerpts, and omission receipts.
- Improved branch PR supervision across early PR creation, protected-main checks, provider merge handoff, hosted close, queue recovery, base synchronization, and deterministic cleanup.
- Improved compatibility handling for Workflow v1, task README v2, historical runner artifacts, and the 0.6.24-to-0.7 migration path without duplicating active branches or worktrees.
- Improved release readiness with mandatory dependency closure, eight installed migration scenarios, architecture ratchets, release-critical tests, exact-SHA publishing, and post-publish audits.
- Adopted native TypeScript 7.0.2 for repository typechecking while retaining TypeScript 6.0.3 for compiler-API consumers such as lint and dependency analysis.
- Rejected speculative preparation caches that failed the measured five-percent end-to-end threshold, keeping mutable task, Git, provider, policy, authority, and semantic truth live.

## Fixed

- Removed automatic semantic pass verdicts and prevented claimed agent checks from being promoted into supervisor-observed evidence.
- Closed sandbox and command-authority gaps that could expose broader read, write, Git, provider, or lifecycle capabilities than the active phase requires.
- Prevented stale fingerprints, stale evaluator packets, root lifecycle drift, base-sync merges, and task-artifact-only commits from corrupting the reviewed implementation boundary.
- Fixed direct and branch PR recovery paths so completed agent or provider operations are not replayed after restart and unresolved effects remain blocked until explicitly resolved.
- Fixed context ingestion and assimilation recovery so deterministic apply, lint, indexing, checks, semantic evaluation, and rollback resume from the first incomplete phase.
- Fixed provider publication and integration edge cases around divergent heads, stale PR identities, hosted-close tails, unresolved review threads, queue leases, and merged cleanup proof.
- Fixed large-repository artifact handling by bounding subprocess buffers and preserving deterministic evidence instead of truncating or overflowing release gates.
- Assimilated the compatible 0.6.25 and 0.6.26 maintenance fixes into the 0.7 line without importing divergent version metadata or weakening the 0.7 contracts.

## Upgrade Notes

- Install the exact stable version with `npm install --global agentplane@0.7.0`; pin the same version in CI and automation.
- Run `agentplane upgrade --dry-run`, then `agentplane upgrade --yes --migrate-task-docs` from the base checkout, followed by a second dry run and `agentplane doctor`.
- Workflow v1 remains readable, but supported writers emit Workflow v2; use `agentplane workflow migrate` for an idempotent receipt-backed migration with exact-byte rollback.
- Task README v2 remains migratable through the explicit task-document migration path; current writers emit README v3 without dropping the legacy body.
- Existing active direct and branch PR tasks keep their identity, owner, route, branch, and worktree; use `task brief`, `task next-action --explain --remote`, and `work resume` instead of creating replacements.
- New work orders and semantic results use version 2 contracts; new workflow steps, state fingerprints, and knowledge references use version 1 contracts.
- External side effects now require current authority records. Scripts that previously inferred permission from plan state or model output must follow the emitted authority and next-action route.
- `evaluator execute` runs a read-only evaluator episode; `evaluator run` remains a compatibility recorder and does not invoke a model.
- The legacy Agentplane loops controller is not imported and no `ap loop` compatibility surface is added; bounded supervision is implemented inside the typed workflow supervisor.
- Maintainer typechecking uses native TypeScript 7.0.2. Compiler-API tools remain on TypeScript 6.0.3, and `AGENTPLANE_TYPESCRIPT_PACKAGE=typescript bun run typecheck` provides the immediate diagnostic fallback.

## Verification

- The executable 0.7 release closure contains 72 mandatory task records and 60 implementation or release leaves; superseded beta milestone tasks are explicitly optional and do not replace the completed RC.2 gate.
- RC.2 proved 70 of 70 transitive dependency outcomes, 27 of 27 provider token cells, 170 of 170 scalar cells, and 50 replay runs without a verified-success, safety, compatibility, or architecture regression.
- Two raw RF-04 latency thresholds remain above baseline and are preserved as diagnostic-only; there are zero blocking RF-04 failures and no latency-improvement claim.
- The reviewed candidate passed the 99-chunk release CI base, 50 workflow tests, 204 significant-file tests, 16 release-critical tests, the eight-scenario installed migration matrix, TypeScript 7 typechecking, guards, schemas, architecture, documentation, and package checks.
- Publication is allowed only after the release candidate is merged to protected main and the GitHub workflow is dispatched with the exact canonical release SHA.
- Post-publication acceptance requires npm parity for agentplane, @agentplaneorg/core, and @agentplaneorg/recipes, the v0.7.0 tag and GitHub Release, installed smoke tests, postpublish audit, hosted-close evidence, and clean local and remote main readback.
