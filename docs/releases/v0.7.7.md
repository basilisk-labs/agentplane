# Release Notes — v0.7.7

## Summary

- AgentPlane 0.7.7 hardens autonomous `branch_pr` execution so a task starts only from an exact upstream base, carries only its own task artifacts, and is considered integrated only when the provider pull request is actually merged.
- Task authority and routing now resolve from the trusted base checkout, including commands launched from stale linked worktrees, while `authority.mode=all` continues to authorize the complete safe autonomous route, including `integration.enqueue`.
- Stable patch publication now enforces release-channel semantics and automatically opens the next beta development version after public release evidence is recorded.

## Added

- Added fail-closed ownership checks that reject foreign committed `.agentplane/tasks/**` artifacts before PR synchronization or integration.
- Added an automated post-release transition that opens the next patch beta version across all managed version surfaces.
- Added regression coverage for stale-worktree routing, autonomous integration authority, provider merge truth, and release-channel version rules.
- Added a typed `blocker.scope_extension_request` and explicit `task scope-extend` operator path so an autonomous agent can request narrowly bounded extra write authority without silently widening its own scope.

## Improved

- Required a task worktree base branch to match its upstream exactly instead of accepting locally ahead or behind bases.
- Made planner classification arrays order-insensitive while preserving classification immutability and allowing execution-contract refinement.
- Made task lookup recover through the primary checkout when a command is launched from an obsolete linked worktree, even when the requested task branch is globally visible in another worktree.
- Consolidated release semver handling and generated a current compatibility candidate for the 0.7 line.

## Fixed

- Fixed local squash integration marking task metadata as merged while the corresponding GitHub pull request remained open.
- Fixed configured authority being read from a mutable task checkout instead of the trusted base checkout.
- Fixed signed approval receipt expectations in task-advance and planner-intent command tests.
- Fixed stable release checks accepting prerelease versions or leaving development surfaces on the released stable version.
- Fixed prerelease commits entering stable-only release-ready, task-registry, release-note, or npm registry detection instead of completing the publish detector as a clean no-op.
- Fixed verified completed tasks becoming unrecoverable when their current provider PR conflicts before an integration-queue handoff exists.
- Fixed advanced-base task artifacts being misclassified as foreign deletions owned by the candidate branch.

## Upgrade Notes

- No user action is required. Existing `authority.mode=all` projects retain full autonomous routing, but authority is now resolved from the canonical base checkout.
- A `branch_pr` task with a locally divergent base must be rebased or recreated from the exact upstream base before work can start.
- PR synchronization and integration now fail with `foreign_committed_task_artifacts` when a branch contains task records outside its declared ownership set.
- `authority.mode=all` still covers `integration.enqueue`, but `task.scope.extend` always requires an exact state-bound USER grant.

## Verification

- Qualified with type checking, focused authority/routing/provider/release suites, the release-critical and critical suites, and the complete fast suite: 570 test files and 4,193 passing tests with one intentional skip.
- Release parity, schema projections, specification examples, routing policy, formatting, and compatibility candidate checks pass for `0.7.7-beta.1` before the stable release freeze.
