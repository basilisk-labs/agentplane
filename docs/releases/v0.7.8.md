# Release Notes — v0.7.8

## Summary

- AgentPlane 0.7.8 introduces task-scoped autonomous execution after one approved plan, with explicit execution grants, bounded operation leases, and re-approval only when the accepted scope materially changes.
- The task-centric supervisor now carries implementation, verification, evaluator rework, scope extension, and completion evidence through one state-bound route while preserving exactly-once external-result and provider-effect semantics.
- GitHub and GitLab change-request handling now shares a provider-neutral lifecycle, while base-checkout, worktree, rebase, and cleanup recovery fail closed on ambiguous repository or provider state.
- The public homepage and root README now explain the authority-to-proof workflow more directly, including the boundary between semantic agent work and deterministic CLI transitions.

## Added

- Added `PlanProposal`, task-scoped `ExecutionGrant`, and operation-lease authority so an approved plan can continue autonomously through bounded implementation, verification, evaluator review, and logical closeout.
- Added task-local execution context and workspace allocation with primary-checkout recovery, exact base identity, and path-independent task routing.
- Added provider-neutral GitHub pull-request and GitLab merge-request lifecycle handling, including mergeability validation and provider-specific transport evidence.
- Added AP-TE Lite guidance to the framework agent instructions and expanded doctor diagnostics for execution authority and self-hosting recovery.

## Improved

- Made task creation, branch status, scope extension, plan refinement, and WorkItem selection resolve through canonical task-centric state instead of reconstructing lifecycle state from prose or checkout location.
- Made evaluator rework preserve the reviewed implementation identity, accept evidence-only follow-up after a committed implementation, and reject stale or overstated verification receipts.
- Made local CI scheduling and runtime claims deterministic under supervisor load while retaining the exact failing group and check evidence.
- Made packaged-candidate verification contracts refresh correctly after managed upgrades and strengthened the maximum-assimilation compatibility gate for the 0.7 line.
- Redesigned the homepage around a responsive authority-to-proof path with clearer evidence storytelling, compact navigation, and restrained semantic color accents.

## Fixed

- Fixed idempotent external-result acceptance for task-centric Tasks without a schedulable WorkItem.
- Fixed material plan refinement returning to the wrong lifecycle phase and fixed approved scope extensions not propagating into the canonical WorkItem plan.
- Fixed task lookup and new-task creation from stale or non-primary worktrees, plus local branch status after merged cleanup.
- Fixed GitHub rebase cleanup rejecting equivalent tree identities and fixed live GitLab merge-request transport and provider-neutral mergeability validation.
- Fixed verification receipts claiming checks that were not observed and fixed evidence-only rework being rejected after implementation was already committed.
- Fixed aggregate local CI losing deterministic failing-group evidence and reduced supervisor-load interference between release-critical check groups.

## Upgrade Notes

- No manual migration is required for normal repositories. Existing task records remain supported through compatibility projection while new task-centric authority and execution context are adopted.
- A single plan approval authorizes only the accepted task scope. Material scope, architecture, risk, dependency, or external-effect changes still require a new state-bound approval.
- Provider effects remain fail-closed: after a timeout or ambiguous response, use AgentPlane readback and reconciliation instead of repeating a merge, tag, or publication blindly.
- Commands that create or integrate `branch_pr` work must run from the canonical base checkout and must preserve exact base and provider identity.
