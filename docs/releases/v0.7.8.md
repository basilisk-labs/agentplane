# Release Notes — v0.7.8

## Summary

- AgentPlane 0.7.8 completes the task-centric refactoring roadmap: one approved semantic plan now drives bounded autonomous execution while AgentPlane retains deterministic authority over lifecycle transitions, verification, integration, and closeout.
- Task execution is bound to logical repository identity and frozen task context instead of checkout paths, with isolated workspaces, operation leases, resumable supervision, material-drift approval, and explicit recovery semantics.
- GitHub and GitLab change-request flows now share a provider-neutral lifecycle, including exact-head checks, mergeability normalization, SHA-guarded integration, external-merge reconciliation, and safer cleanup after rebase merges.
- The release also fixes scope-extension approval, evaluator rework, packaged-candidate verification, primary-checkout task creation, post-merge diagnostics, task-artifact-aware finish recovery, semantic type-module naming, and the first-task documentation path uncovered during qualification.

## Added

- Added structured `TaskPlanProposal` work graphs, host-originated user decisions, task-scoped `ExecutionGrant` and `OperationLease` authority, and a resumable supervisor loop from approved plan through logical closeout.
- Added task execution and workspace allocation contexts so semantic authority remains stable across paths, worktrees, repository relocation, and isolated direct or branch-PR execution.
- Added provider-neutral GitHub and GitLab pull-request and merge-request adapters with idempotent discovery, exact-head hosted checks, guarded merge, and typed provider failures.
- Added AP-TE Lite instructions and architecture guards that keep agent reasoning semantic while the CLI owns deterministic lifecycle mechanics.

## Improved

- Made execution strategy task-owned and risk-adaptive, with deterministic escalation and one serialized integration queue rather than user-selected repository routes.
- Improved verification identity, evaluator provenance, plan refinement, rework recovery, and finish recovery so lifecycle-only changes cannot silently invalidate or reuse unrelated evidence.
- Routed task creation through the primary checkout and made cleanup accept exact tree identity after GitHub rebase merges without weakening commit, receipt, or negative guards.
- Refreshed the clone baseline after the completed roadmap added 67 measured sources; duplication percentage improved while the intentional absolute-count growth is now qualified by the full CI contract.
- Improved the README and homepage around the authority-to-proof workflow, clearer semantic-agent boundaries, responsive evidence storytelling, and the contract-tested first-task example.

## Fixed

- Fixed material and nonmaterial scope-extension handling so stale grants are replaced safely, approval provenance is preserved when valid, and completion-contract drift requires fresh authority.
- Fixed evaluator blocked routing and legacy execution-grant migration so logical repository identity is used consistently after upgrades and workspace moves.
- Fixed GitLab JSON request headers and provider-specific mergeability interpretation while preserving the established GitHub behavior.
- Fixed packaged candidate verification-contract refresh, stale post-merge route diagnostics, mutual task README ownership, and recovery of prepared finish requests.
- Fixed finish recovery so reviewed task-artifact descendants remain valid only when they preserve the evaluated implementation ancestry, including linked batch task artifacts without weakening implementation-hash checks.
- Restored the generic `types.ts` filename guardrail by moving task execution and workspace allocation contracts to semantic `model.ts` modules while preserving their readonly API shape.

## Upgrade Notes

- No manual migration is required for normal projects. AgentPlane migrates compatible task authority and execution context while failing closed on ambiguous or material drift.
- Existing GitHub workflows remain supported. GitLab support uses the configured publication remote and the existing `glab` authentication session without reading or storing tokens.
- Install or update all public packages to exactly `0.7.8`; internal package pins are released in lockstep.

## Verification

- The release candidate must pass `bun run release:prepublish`, package parity and availability checks, exact-head hosted PR checks, protected-main integration, and the hosted npm publish workflow on the exact merged release SHA.
- Post-publication acceptance requires independent Git tag and GitHub Release readback, npm registry parity for `agentplane`, `@agentplaneorg/core`, and `@agentplaneorg/recipes`, published-package smoke, platform audit, and an installed CLI smoke outside the repository.
