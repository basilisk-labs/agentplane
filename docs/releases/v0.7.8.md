# Release Notes — v0.7.8

## Summary

- AgentPlane 0.7.8 completes the task-centric refactoring roadmap: an approved semantic plan now drives bounded work while AgentPlane owns lifecycle transitions, authority, validation, atomic effects, integration, and closeout.
- Task execution is bound to logical repository identity and frozen task context rather than checkout paths, with isolated workspaces, operation leases, resumable supervision, drift approval, and explicit recovery semantics.
- GitHub and GitLab change-request flows now share provider-neutral discovery, exact-head checks, mergeability normalization, SHA-guarded integration, external-merge reconciliation, and safer cleanup.
- Existing `context.maximum_assimilation` behavior is protected by a compatibility E2E through the new task-centric core. The follow-up Knowledge Assimilation subsystem is intentionally not part of this patch release.

## Added

- Added canonical task-centric contracts for `Task`, approved `TaskPlanRevision`, `WorkItemGraph`, execution grants, operation leases, actor ports, validation evidence, effect receipts, and deterministic orchestration.
- Added a resumable supervisor loop that issues bounded semantic WorkOrders and applies schema-valid results while keeping formal state changes in the CLI.
- Added task execution and workspace allocation contexts so authority remains stable across paths, linked worktrees, repository relocation, and isolated direct or branch-PR execution.
- Added provider-neutral GitHub and GitLab pull-request and merge-request adapters with idempotent discovery, exact-head hosted checks, guarded merge, and typed provider failures.
- Added AP-TE Lite instructions and architecture guards that keep semantic agents independent of deterministic lifecycle mechanics.
- Added one compatibility E2E proving that the existing `context.maximum_assimilation` contract completes through the task-centric execution path without replacing its contracts, prompts, schemas, artifacts, provenance, or verification gates.

## Improved

- Made execution strategy task-owned and risk-adaptive, with deterministic escalation and a serialized integration lane instead of user-selected repository routes.
- Made external-agent result application select the active WorkItem deterministically and preserve its output, verification, and completion provenance across resumptions.
- Improved verification identity, evaluator provenance, plan refinement, rework recovery, and finish recovery so lifecycle-only changes cannot silently invalidate or reuse unrelated evidence.
- Routed task creation through the primary checkout and isolated task-owned artifacts so sibling tasks cannot inherit each other's uncommitted README state.
- Made cleanup accept exact tree identity after GitHub rebase merges while retaining commit, receipt, ancestry, and negative guards.
- Improved packaged-candidate verification, stale post-merge route diagnostics, linked-task-artifact ancestry, and recovery of prepared finish operations.
- Refreshed the clone baseline for the completed roadmap and retained full compatibility and policy gates for the larger task-centric implementation surface.
- Improved the README and homepage around the authority-to-proof workflow, semantic-agent boundaries, responsive evidence presentation, and the contract-tested first-task path.

## Fixed

- Fixed external semantic results with a null WorkItem identifier being treated as ambiguous even when exactly one active WorkItem exists; multiple active candidates still fail closed.
- Fixed direct and external verification recording so required evidence is retained, matched to the correct WorkItem, and independently testable after result application.
- Fixed material and nonmaterial scope-extension handling so stale grants are replaced safely, valid approval provenance is preserved, and completion-contract drift requires fresh authority.
- Fixed evaluator blocked routing and legacy execution-grant migration so logical repository identity is used consistently after upgrades and workspace moves.
- Fixed GitLab request headers and provider-specific mergeability interpretation while preserving established GitHub behavior.
- Fixed finish recovery so reviewed task-artifact descendants remain valid only when they preserve evaluated implementation ancestry.
- Fixed mutual task README locking, stale verification reuse after rework, valid-Git blueprint test fixtures, task-artifact-aware finish recovery, and cleanup fallback when a provider fetch URL is unavailable.
- Restored semantic module names for task execution and workspace allocation contracts while preserving their readonly public API shape.

## Upgrade Notes

- No manual migration is required for normal projects. Compatible task authority and execution context are migrated automatically, while ambiguous or material drift continues to fail closed.
- Existing context repositories and `context.maximum_assimilation` inputs remain supported; no Knowledge Assimilation migration is introduced in 0.7.8.
- Existing GitHub workflows remain supported. GitLab support uses the configured publication remote and the existing `glab` authentication session without reading or storing tokens.
- Install or update all public packages to exactly `0.7.8`; internal package pins are released in lockstep.

## Verification

- The release candidate must pass `bun run release:prepublish`, package parity and availability checks, exact-head hosted PR checks, protected-main integration, and the hosted npm publish workflow on the exact merged release SHA.
- The compatibility gate exercises `context.maximum_assimilation` end to end through the task-centric core and verifies the legacy artifacts and completion evidence.
- Post-publication acceptance requires independent Git tag and GitHub Release readback, npm registry parity for `agentplane`, `@agentplaneorg/core`, and `@agentplaneorg/recipes`, published-package smoke, platform audit, and an installed CLI smoke outside the repository.
