# Release Notes — v0.6.30

## Summary

- Windows task worktrees now reuse a repository `node_modules` layout only when AgentPlane can prove that the layout and every declared direct dependency remain owned by the repository.
- Worktree startup still supports the existing junction-based fast path for a valid repository-local install, while unsafe or incomplete candidates fall back without creating a junction.
- The 0.6 maintenance line now carries the same proven install-layout ownership guard used by the newer runtime, without importing unrelated v0.7 behavior.

## Added

- Added focused coverage for a complete repository-local install, another task worktree as a source, external workspace and dependency targets, and missing or incomplete dependency packages.

## Improved

- Reusable install discovery now checks the real paths of the source layout and each direct dependency before linking them into a task worktree.
- Release task evidence records the exact implementation commit, local declared checks, hosted Linux and Windows checks, and the independent evaluator verdict used for the maintenance merge.

## Fixed

- Fixed task worktree materialization accepting a `node_modules` directory that resolves into another task worktree or outside the repository.
- Fixed incomplete install candidates being treated as reusable when a declared dependency directory or its package manifest is missing.
- Preserved the existing pre-removal unlink defense so cleanup cannot recursively traverse a linked or junction-backed install layout.

## Upgrade Notes

- No configuration or data migration is required.
- The published package set moves from `0.6.29` to `0.6.30`.
- Projects with a valid repository-local install keep the fast reuse path; other layouts are skipped and can be installed normally inside the task worktree.

## Verification

- The implementation task completed focused guard tests, the 92-test platform-critical suite, policy routing, and the full local CI suite before merge.
- GitHub Core CI passed contract, static, unit, critical CLI, workflow, coverage, Windows, and aggregate PR verification on the final maintenance PR head.
- Release planning stopped when the local `v0.6.29` reference was unavailable, then resumed only after the exact published tag was restored and verified against commit `69d023b1de5450a63244e8443662021fba484f81`.
