# Release Notes - v0.7.5

## Summary

- AgentPlane 0.7.5 makes the supervisor route the single normal task workflow: the CLI owns lifecycle, authority, Git, verification, evidence, and recovery while agents receive bounded semantic episodes.
- New-task and initialization UX now starts from user intent, explains the selected execution route, and applies repository-derived safe defaults without requiring users or agents to reconstruct the process.
- This cumulative patch also hardens Windows task discovery, concurrent task creation, compatibility retirement, and local evidence retention before the next feature family is introduced.

## Added

- Added an external-agent protocol through `agentplane task advance <task-id> --agent-json`, with an exact `result_path`, structured `resume_argv`, state fingerprint, scoped authority, and typed result contract.
- Added managed supervision through `agentplane task run <task-id>` on the same route and execution journal used by external agents.
- Added explainable automatic task routing that selects `direct` or `branch_pr` from the requested work, repository policy, and risk signals while keeping explicit user choices authoritative.
- Added a user-first task intake flow and execution preview so a natural-language request can be inspected before AgentPlane creates or starts durable work.
- Added repository-derived `init` defaults and progressive setup prompts that keep the common path short while retaining advanced policy and runner configuration.
- Added semantic policy projection for PLANNER, EXECUTOR, and EVALUATOR episodes, including project purpose, scope, security constraints, required inputs, writable roots, output schema, and stop rules without control-plane choreography.
- Added `agentplane evidence stats`, `agentplane evidence compact`, and `agentplane evidence gc` with content-addressed retention, deduplication, pinning, writer serialization, and race-safe revalidation.
- Added bounded compatibility classifications and retirement blockers so current runtime adapters, lazy historical readers, and planned 0.8 removals are distinguishable through `agentplane doctor legacy`.
- Added observed token accounting to completed task output, sourced from the persisted supervisor journal rather than agent estimates.

## Improved

- Reworked bundled `AGENTS.md`, direct and branch-PR policy modules, role guidance, the Codex skill, quickstart text, and lifecycle documentation around `task active`, `task advance`, and `task run` as the canonical happy path.
- Reduced the default task help surface to the canonical `new`, `active`, `advance`, `run`, and `brief` operations while preserving diagnostics and compatibility commands behind the full help surface.
- Improved approval boundaries with typed operator actions and corrected explicit plan provenance so human-supplied planning is not attributed to an agent.
- Improved branch-PR supervision so one advance from the base checkout prepares the worktree and returns a WorkOrder whose repository revision, writable roots, source manifest, and exchange all target that worktree.
- Improved verification parsing and execution receipts so claimed semantic outcomes cannot substitute for AgentPlane-observed checks or independent evaluator review.
- Improved prompt qualification to inspect the exact compiled provider input and reject embedded lifecycle, Git, PR, verification, integration, cleanup, and release choreography.
- Improved task creation serialization with process-domain-aware lock ownership and fail-closed recovery when a stale owner cannot be verified safely.

## Fixed

- Fixed Windows task scans comparing rounded numeric inode values with exact `BigInt` file identities, which could mark readable README files as unreadable on NTFS.
- Fixed stale task-creation locks being recoverable across unrelated hosts or process domains without enough evidence that the recorded owner was gone.
- Fixed recovery marker publication so interrupted writers cannot expose partial marker contents as committed evidence.
- Fixed ambiguous or unknown automatic intent being silently promoted into executable work; AgentPlane now returns a confirmation boundary instead.
- Fixed generated agent instructions and managed provider prompts that still taught agents to call `start-ready`, `work start`, `verify`, `finish`, `integrate`, Git, or PR lifecycle commands during normal semantic work.
- Fixed external protocol responses that required agents to interpolate placeholder paths or rebuild the resume shell command.
- Fixed evidence garbage collection races that could remove newly referenced or concurrently written objects.

## Upgrade Notes

- No migration is required. Upgrade with `npm install --global agentplane@0.7.5`.
- Existing 0.6.x and 0.7.x repositories remain supported by the compatibility and upgrade fixtures. `agentplane doctor legacy` identifies adapters that should be migrated before their declared retirement release.
- Manual lifecycle commands remain available as operator, recovery, and compatibility interfaces, but generated agent guidance now treats supervisor-driven `task advance` or `task run` as the normal route.

## Verification

- The release candidate is gated on the full local CI and release-extra suites, package installation and migration matrices, critical CLI, Windows, documentation, CodeQL, static analysis, unit, workflow, and compatibility checks on the exact release SHA.
- The bounded semantic qualification executes 50 replay runs and 55 provider episodes across direct and branch-PR workflows, managed and external frontends, stale state, interruption, effect uncertainty, evaluator rework, hosted waits, and cleanup races without retrying failed semantic episodes.
- Qualification compares provider tokens, verified success, scope violations, golden mismatches, rework, harness setup, first scoped mutation, and time to verified result against the frozen 0.7 baseline. The historical RF-04 first-mutation sample-count delta remains diagnostic-only; all blocking latency and quality gates must pass before publication.
