## Status

Planned implementation of [ADR 0018](../adr/0018-feature-deliveries-and-semantic-routing.md).
The [delivery specification](./feature-deliveries.mdx) is the architectural contract.
This backlog does not implement or authorize execution of the feature.

## Executable representation

The companion `docs/developer/feature-delivery-plan.json` is a compact v2 Plan input.
It contains 15 canonical WorkItems, explicit dependency edges, output IDs, scope roots, acceptance
criteria, and focused verification commands. Import it with the supported `task create --plan-file`
operator interface. The CLI assigns the canonical Task ID and repository baseline.
Creation does not approve or start implementation. Do not manually edit task-state artifacts.

The WorkItems are atomic implementation tasks inside one canonical implementation Task.
They are distinct from the future independent Tasks that can join a feature Delivery.
Dependencies are enforced in the WorkItem graph rather than represented only in prose.

## Execution rules

Use a fresh supervisor packet for each semantic episode. Keep changes within the WorkItem scope.
A failed dependency blocks its consumers. Add each named regression suite during its implementation;
the test paths are planned deliverables and are not present or passing by virtue of this document.
Use the repository-native checks in addition to the focused contract where required by the packet.
Do not skip a missing suite or use a pass-with-no-tests option.

Each result records changed paths, verification commands and outcomes, evidence digests, and residual
risks. Deliver one reviewable outcome per WorkItem. Preserve existing task and provider behavior until
the relevant rollout gate passes. No external writes are authorized by this backlog.

## Atomic contracts

### DLV-01: Define the Delivery domain contract

Depends on: none.
Output: `dlv-01-result`.

Integration area: Existing Task Kernel domain and generated contract schemas.

Scope: `packages/core/src/tasks`, `packages/core/schemas`, `packages/spec/schemas`, `schemas`.

Acceptance:

- Add versioned path-neutral Delivery identity, membership, route decision, candidate, state and receipt contracts using the existing schema source of truth.
- Pure transitions enforce OPEN, READY, INTEGRATING, INTEGRATED and RETIRED invariants without a second Task state machine.
- Reject invalid transitions and duplicate member identity; round-trip fixtures and deterministic replay pass.

Focused verification:

```bash
bun run test:project core packages/core/src/tasks/delivery-contract.test.ts
```

### DLV-02: Persist delivery ownership atomically

Depends on: DLV-01.
Output: `dlv-02-result`.

Integration area: Task backend transactions and canonical delivery registry.

Scope: `packages/agentplane/src`.

Acceptance:

- Persist Delivery revisions and task bindings through existing backend transaction boundaries.
- Enforce unique active task membership and branch/workspace ownership with compare-and-swap.
- Concurrent bind attempts have one winner; retry and crash after persistence return the same receipt.

Focused verification:

```bash
bun run test:project agentplane packages/agentplane/src/commands/task/delivery-store.test.ts
```

### DLV-05: Bind tasks and adopt explicitly selected feature branches

Depends on: DLV-02, DLV-04.
Output: `dlv-05-result`.

Integration area: Canonical task intake and delivery membership commands.

Scope: `packages/agentplane/src`.

Acceptance:

- Create or join an OPEN delivery through typed commands; validate existing branch ownership and preserve its commits.
- Bind independent Tasks before execution; record immutable intake base and distinct delivery start head.
- Duplicate requests return the existing binding; incompatible targets and conflicting owners fail without creating another branch.

### DLV-06: Reuse delivery workspaces under fenced writer leases

Depends on: DLV-05.
Output: `dlv-06-result`.

Integration area: Workspace allocator and lease adapter.

Scope: `packages/core/src/git`, `packages/agentplane/src`.

Acceptance:

- Allocate one worktree per shared delivery and resolve TODO membership before task-local worktree preparation.
- Lease acquisition binds task attempt, expected head and fencing token; concurrent and stale writers cannot mutate the checkout.
- Restart, changed title and repository relocation recover the recorded branch and workspace without duplicate allocation.

### DLV-07: Execute independent member tasks sequentially

Depends on: DLV-06.
Output: `dlv-07-result`.

Integration area: Supervisor and WorkOrder routing.

Scope: `packages/agentplane/src/commands/task`, `packages/agentplane/src/commands/shared`, `packages/agentplane/src/runner`.

Acceptance:

- Execute A then B in one delivery; B begins at the accepted A head with its own Plan and execution grant.
- Require accepted result, persisted evidence and accounted-for clean state before writer handoff; failed or dirty A blocks B.
- Completing a member neither merges nor cleans the delivery; adding C to OPEN reuses the same workspace.

Acceptance:

### DLV-10: Integrate each delivery exactly once through its gate

Depends on: DLV-09.
Output: `dlv-10-result`.

Integration area: Existing integration queue and provider adapters.

Scope: `packages/agentplane/src`.

Acceptance:

- Use one serialized reservation per delivery; direct uses the existing queue and branch_pr uses the provider as sole merge authority.
- Guard provider merge with exact candidate identity, reconcile its receipt and synchronize the local target; never fall back to local merge.
- Head/base movement, unavailable provider, and a crash after successful merge preserve recoverable state; retries cannot duplicate the merge.

## Rollout gates

1. DLV-01 through DLV-05 admit and persist delivery identities without enabling execution.
2. DLV-06 through DLV-09 qualify shared execution and candidate validity behind rollout control.
3. DLV-10 through DLV-14 qualify integration, migration, recovery, UX and the complete lifecycle.
4. DLV-15 reduces measured overhead after correctness is established.

Rollback stops new delivery admission and preserves accepted bindings, unique work and operation
receipts. It never re-enables concurrent writes in a shared checkout or fabricates provider success.

## Non-goals

This roadmap does not change repository policy to allow direct mode, deploy a release, rewrite
existing Git history, or automatically merge an implementation PR. Those actions need their own
matching operator authority. It does not introduce a separate autonomous routing agent.
